The simplest way to look around inside a running workspace is to open a Bash
shell with the Run:ai CLI. This connects directly to the workspace's main pod;
you do not need to install or configure an SSH server in the container.

Before connecting, [install and sign in to the Run:ai
CLI](/access/cli/#install-the-runai-cli), connect eduVPN when required, and
confirm in the Run:ai portal that the workspace is **Running**.

## Open a shell in a running workspace

Find the workspace name, then open a shell:

```bash
runai workspace list --project PROJECT_NAME
runai workspace bash WORKSPACE_NAME --project PROJECT_NAME
```

You are now running Bash inside the workspace's main pod. From here you can
inspect the filesystem, check the mounted data, or verify that the GPU is
visible:

```bash
pwd
ls -la
nvidia-smi
```

Type `exit` to leave the shell. This disconnects your terminal but does not
stop the workspace. If the workspace has more than one pod, select one
explicitly:

```bash
runai workspace bash WORKSPACE_NAME \
  --project PROJECT_NAME \
  --pod POD_NAME
```

See NVIDIA's [`runai workspace bash`
reference](https://run-ai-docs.nvidia.com/self-hosted/reference/cli/runai/runai_workspace_bash)
for the available options.

## Advanced: Connect to the SSH container

SSH is only available when the workspace uses an image that runs an SSH
server. Spike provides an [SSH-container
example](/downloads/ssh-container/README.md) for this purpose; a regular
workspace image does not need SSH. The [Podman and Harbor
guide](/images/podman-harbor/#ssh-container-example-location) links all files
needed to build the example.

Once that SSH-enabled workspace is **Running**:

1. Connect [eduVPN](https://www.surf.nl/en/getting-started-with-eduvpn) when
   required by your location, then run `runai login`.
2. Keep the port forward open in one terminal:

   ```bash
   runai workspace port-forward WORKSPACE_NAME \
     --project PROJECT_NAME \
     --port 2222:2222
   ```

3. In a second terminal, connect with the private key matching the public key
   added when the SSH-container image was built:

   ```bash
   ssh -i ~/.ssh/id_ed25519 developer@localhost -p 2222
   ```

Keep the forwarding terminal open while using SSH. Reconnect by checking that
the workspace is still **Running**, then start the port forward again.

For moving files rather than opening a shell, follow the complete [File
transfer guide](/storage/file-transfer/).

:::caution
Never paste a private key, password, or access token into a ticket, notebook,
terminal history shared with others, or this documentation repository.
:::
