Hosted models are inference deployments operated by SCC AI Engineers. You may
be given access to an endpoint or user interface, but you must not create,
resize, restart, reconfigure, or delete the underlying inference workload.

Availability, model revisions, request limits, and accounting can change. Ask
your SCC AI Engineer which endpoint and model are approved for the project
instead of copying an identifier from another project or an old example.

## Current service information

Use the [Spike hosting project in TU/e GitLab](https://gitlab.tue.nl/hpclab/llm-hosting/spike-hosting)
for the user-facing service README and current hosted-model status. TU/e GitLab
may ask you to sign in. The repository reports what the service currently
exposes; it does not grant access or replace project approval and onboarding.

Use this page for safe client guidance and the GitLab project for live service
information. If they appear to disagree, stop and ask your SCC AI Engineer
before sending data or building a dependency on an endpoint.

## Before sending a request

Confirm:

1. The model is approved for the intended research purpose.
2. The input and output data are allowed to be processed by this service.
3. The endpoint, authentication method, and request limits came from the SCC
   onboarding or support channel.
4. The client will not log tokens, sensitive prompts, or model responses.
5. A small harmless request succeeds before starting a batch or benchmark.

:::caution
An access token is a secret. Keep it out of notebooks, repositories, images,
tickets, screenshots, and shared terminal history. Use the approved credential
mechanism and rotate a token that may have been exposed.
:::

## Discover available model identifiers

For an OpenAI-compatible endpoint, keep the issued values in local environment
variables:

```bash
export HOSTED_MODEL_BASE_URL='https://approved-endpoint.example/v1'
export HOSTED_MODEL_TOKEN='provided-through-the-approved-flow'
```

List the models currently exposed by that endpoint:

```bash
curl --fail --silent \
  -H "Authorization: Bearer ${HOSTED_MODEL_TOKEN}" \
  "${HOSTED_MODEL_BASE_URL}/models"
```

Use only an identifier returned by discovery and approved for the project.

## Send a small request

```bash
curl --fail --silent \
  -H "Authorization: Bearer ${HOSTED_MODEL_TOKEN}" \
  -H 'Content-Type: application/json' \
  "${HOSTED_MODEL_BASE_URL}/chat/completions" \
  -d '{
    "model": "MODEL_FROM_DISCOVERY",
    "messages": [
      {"role": "user", "content": "Return the word ready."}
    ]
  }'
```

Set an application timeout and handle rate limits and service errors. Do not
retry indefinitely. Large batches and load tests require prior coordination
with the SCC AI Engineer managing the endpoint.

The backend may use [vLLM's OpenAI-compatible
server](https://docs.vllm.ai/en/latest/serving/openai_compatible_server.html),
but the SCC-provided endpoint and policy remain authoritative. When access is
provided through Open WebUI, use its [official user
documentation](https://docs.openwebui.com/) and the SCC-issued sign-in flow.

## What to report when requesting help

Share the time of the request, the endpoint hostname, model identifier, HTTP
status, and a redacted error message. Do not include the bearer token or
sensitive prompt content. SCC AI Engineers can inspect and change the
deployment; researchers should not attempt to repair it through Run:ai.
