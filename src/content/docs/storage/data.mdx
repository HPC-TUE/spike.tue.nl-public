Choose storage before submitting a workload. The storage choice determines
whether your data survives a restart, retry, or deletion.

| Storage choice | Use it for | Lifecycle |
| --- | --- | --- |
| Existing data source | Project datasets and shared inputs | Managed outside one workload; verify permissions before use. |
| Persistent volume | Checkpoints, repeatable outputs, and long-lived work | Survives workload restarts according to project policy. |
| Ephemeral volume | Caches, temporary preprocessing, and disposable scratch data | Removed with the associated workload; never store the only copy of a result. |

## Transfer guidance

Use `scp` for a small, specific transfer to an approved reachable endpoint. For
large datasets, use the project’s established storage path or transfer process;
avoid repeatedly moving copies through a running workload. Before cleanup,
confirm important outputs exist in persistent storage and document the image tag,
command, and input version used to produce them.

Project provisioning, volume creation, resizing, copying, and deletion are
admin operations and are intentionally documented only in the private wiki.
