These terms govern the use of the public Spike documentation website
(`docs.spike.tue.nl`), published by the Eindhoven University of Technology
(TU/e) Supercomputing Center (SCC).

## Purpose and scope

The Spike documentation provides guidance, workflows, and technical references
for researchers, students, and staff conducting research on the Spike GPU
supercomputing environment.

Using this documentation does not automatically grant access to Spike compute
hardware. Access to compute resources, registries, and project storage requires
formal approval through the [Spike intake process](/start-here/intake/).

## Acceptable use

When using this documentation and the systems described herein, users agree to:

- **Follow institutional policy:** Comply with the TU/e Code of Conduct for ICT
  Resources and applicable Dutch and European research regulations.
- **Academic and scientific purpose:** Use platform resources and guidance solely
  for authorized university research, educational, and approved collaborative
  activities.
- **Protect secrets and credentials:** Never commit, publish, or share passwords,
  API tokens, private keys, or personal credentials.
- **Adhere to data governance:** Ensure research datasets have received necessary
  data classification and ethical approvals before transferring them to Spike
  storage, as detailed in [Data classification](/start-here/data-classification/).

## Intellectual property and code samples

Unless otherwise indicated, the documentation content, structure, and
illustrations are the intellectual property of Eindhoven University of
Technology.

Code snippets, example configuration files, and helper scripts provided within
this documentation (such as `Containerfile` examples or storage configuration
templates) are provided for research and operational use within authorized Spike
projects.

## Disclaimers

This documentation is maintained to assist researchers with practical tasks.
However:

- Documentation marked as *Experimental* reflects features or configurations
  subject to evolution, testing, or vendor updates.
- Workload benchmarks and optimization recommendations are illustrative and
  depend on individual model architectures, dataset geometries, and runtime
  configurations.
- The TU/e Supercomputing Center reserves the right to update documentation,
  retire deprecated workflows, and adjust cluster policies as required for
  platform stability and security.
